# Basic Syntax

## Types and Terms

A type is a label or classification for data, defining a class of objects or values that share the same properties. In Lean 4, some basic types are provided:

| Type | Explanation | Example |
|---|---|---|
| `Nat` | National Numbers |  |
| `Int` | Integers |  |
| `Float` | Float/Decimals |  |
| `Char` | Characters | `'a'` |
| `String` | String | `"hello"` |
| `List type` | List with elements of type `type` | `[1, 2, 3] : List Nat` |
| ... | | |

The library *Mathlib4* provides numerous types.

A term of a type is an specific object that follows the properties of the type. For instance, `1.5` is a term of type `flaot`. 

*Remark*: For the positive integers such as `1`, their default type is `Nat`, instead of `Int`.

## Typing Math Symbols
The mathematical symbols in Lean all are all typed by the abbreviation begined with `\`. Users can find the table of the abreviation by
```
Ctrl + Shift + P
Show Unicode Input Abbreviations
```

## Comment Code

Comments in Lean 4 can be typed in both single-line and multi-line:
- Single-line: 

    ```lean
    -- This is a single-line comment
    ```

- Multi-line:

    ```lean
    /-
    This 
    is a
    multi-line
    comment
    -/
    ```

## Lean InfoView

"Lean InfoView" is an interactive status page of Lean 4 in VS code, which shows the current status of the line where the cursor is located. It shows the current goal, callable hypothesis, the messages returned by the kernel and all messages record of the document.

We introduce the concept of "goal" and "hypothesis" later.

## Meta Commands

The commands with prefix `#` are meta commands, which is used to interact with the kernel of lean 4 directly.

In the following, we use the comments to show the outputs.

### #check

`#check` is to inspect the type of an object
```lean
#check true          
-- Bool.true : Bool
#check 3
-- 3 : Nat
#check Nat
-- Nat : Type
#check Type
-- Type : Type 1
```

### #print

`#print` is to show the definition of an object or a type:
```lean
#print Int
/-
inductive Bool : Type
number of parameters: 0
constructors:
Bool.false : Bool
Bool.true : Bool
-/

#print Type
-- error
```
`inductive Bool : Type` tells that Boolean type is an inductive type, and `number of parameters: 0` tells that it does not require any parameters. `constructors:` shows the elements in the type `Bool`. `... : Bool` means that the objects generated by the constructors are of the type `Bool`.

```lean
#print Nat
/-
inductive Nat : Type
number of parameters: 0
constructors:
Nat.zero : Nat
Nat.succ : Nat → Nat
-/
```
`Nat.succ` is a recursive constructor. We will introduce it later.

```lean
#print List
/-
inductive List.{u} : Type u → Type u
number of parameters: 1
constructors:
List.nil : {α : Type u} → List α
List.cons : {α : Type u} → α → List α → List α
-/
```
`List` is also an inductive type that needs one parameter. `Type u → Type u` means that tt is not simply a type, but a type constructor(introduced later) which receive a type and generate another type. `u` here is the universal level which means that `List` are able to handle any types. 

### #eval

`#eval` is to show the value of an expression.
```lean
#eval 1+2
-- 3
```

## `def` command

`def` command is to define a new object. Syntax:
```lean
def name (parameter_1 : type_1) (parameter_2 : type_2) : type_return := value 
```
The parameter of a new definition can be multiple or empty.

### Define a Constant

To define a constant, we can assign a value to a symbol and the parameters not are required. For example
```lean
def e : Float := 2.718281828
#eval e 
-- 2.718282
```
`: Float` indicates the type of `e` and `:= 2.718281828` assigns the value of `e`. Note that the digit of `Float` is 6.

### Define a Function

To define a function, we need to specify the parameter(input) and the expression. For example:
```lean
def sum (x y : Float) : Float := x + y
#eval sum 2 5.6
-- 7.600000
#eval sum 2 10
-- 12.000000
```
Note that the parameters with same type can be typed by `(x y : Float)`. 

We can use `#print` command to inspect the definition of functions
```lean 
#print sum
/- 
def sum : Float → Float → Float :=
fun x y => x + y
-/
```

## `fun` command

`fun` is a command in Lean 4 for anonymous function or so called "lambda" function. In math, we can write a function in the form of mapping, such as $x \mapsto x+1$. `fun` is exactly for this. We can define a function without using `def`. Syntax:
```lean
fun (pamerater_1 : type_1) => expression
-- or equivalently
λ (pamerater_1 : type_1) => expression
```
For example
```lean
#check fun (n : Nat) => n+2
-- fun n => n + 2 : Nat → Nat
```
where `Nat → Nat` means that it is a type receiving `Nat` and returning `Nat`.

### Type of `fun`

Notice that we do not need to specify the type of the output since Lean 4 has a system of type inference. The kernel can inference the suitable type. Nonetheless, we can still specify the type by two ways:
```lean
-- 1:
fun ((pamerater_1 : type_1) => expression : type_fun)
-- 2:
fun (pamerater_1 : type_1) => (expression : type_expression)
```
where the first way is to assign the type of the whole function, and the second way is just to assign the type of the output. For instance
```lean
(fun (n : Nat) => n+2 : Nat → Nat)
fun (n : Nat) => (n+2 : Nat)
```

## Tactics

Tactics are the commands used to process the propositions during proofs. Since a proof is a term, tactics are essentially the commands to construct a term.

We will gradually introduce the detail of Tactics afterward.

Tactic mode is an interactive mode that allows users to interact with the kernel of Lean 4. After entering tactic mode, turnstile symbol `⊢` appears in InfoView to specify the current goal, which is the object that need to be constructed. We can use different tactics to handle the goal. When `no goals` is returned, the proof/construction finishes.

## Function type

If `A` and `B` are types, then `A → B` is a type representing all functions from type `A` to type `B`, and its type depends on the highest level of types in `A` and `B`. For instance
```lean
#check Nat → Float
-- Nat → Float : Type
#check Float → Type
-- Float → Type : Type 1
#check Nat → (Float → Int)
-- Nat → Float → Int : Type
```
We can define functions by constructing the terms(desired functions) of a function type, where the tactics(introduced later) are used. For instance:
```lean 
def sum2 : Nat → Nat → Nat := by
  intro a
  intro b  -- equivalent to: intro a b
  exact a + b
```
Here, we use three tactics: `by`, `intro`, `exact`.
- `by`: is signals that the following part is tactic mode
- `intro`: intoduces the left-hand side part of the goal with `→` 

    When the cursor is on `intro a`, we have the following in InfoView
    ```Lean InfoView
    1 goal
    a : Nat
    ⊢ Nat → Nat
    ```
    which extracts the first `Nat` and let `a` be a variable of type `Nat`, so that the goal switch to `Nat → Nat`.

    And, when that is on `intro b`, we have the following in InfoView
    ```Lean InfoView
    1 goal
    a b : Nat
    ⊢ Nat
    ```

- `exact`: when there is an object that satisfies the current goal, we use `exact ...` to end the proof

    For `exact a + b`, we have the following in InfoView
    ```Lean InfoView
    No goals
    ```
    which means the proof finishes since our current goal is to construct a term of type `Nat`, and `a + b` is exactly in type `Nat`.

Defining objects by function types is useful for the complicated objects. 

## Type Constructors

The world of functions in Lean 4 can be partitioned into two levels:

1. Term level: 

    The functions processing terms, such as `2.72`, `'e'`, `[1, 2, 3]`. The types of these functions are usually turning `Type` to `Type`, such as `Nat → Int`.

    Functions in term level are usually defined by commands `def`, `fun`.

2. Type level: 

    The functions processing types, such as `Bool`, `Nat → Float`, or even the types in higher type universe. These functions receive and return types: `Type u → Type u`, instead of terms. 

    Functions in type level are usually defined by commands `structure`, `inductive`. 

Type constructors are exactly the functions in type level. These functions produce new types, which means types can depend on values(parameters of function) and this is exactly the idea of Dependent Types Theory. This kind of types are called "dependent types".

A classical example is `List`, which is essentially a function with parameters `Type u`. The inputs of `List` can be `Nat`, `Type`, `Type 1`, etc.
```lean 
#check List
-- List.{u} (α : Type u) : Type u
```
The exact type of `List u` depends on the value `u`. 
```lean
#check List Nat
-- List Nat : Type
#check List Type
-- List Type : Type 1
#check List Int → Nat
List Int → Nat : Type
```

## Basic Tactics

### `cases` tactic

`cases` tactic splits the current goal into branches based on the possible values/cases of the input. It inspects all constructors(cases) of the type of the object, and split the goal into several subgoals based on the constructors. `cases` can only be used for the inductive types.

For example, this is a function returning the negation of the input:

```lean 
def BoolNot : Bool → Bool := by
  intro b 
  cases b
  -- b = false
  exact true
  -- b = true
  exact false
```
`intro b` introduces a parameter of `BoolNot`, and InfoView returns:
```
1 goal
b : Bool
⊢ Bool
```
which means the current goal is to construct a `Bool`. Then, `cases b` splits `b` whose type is `Bool` and `Bool` has two constructors: `Bool.false` and `Bool.true`. When the cursor is in `cases b`, InfoView returns
```lean
cases b
/-
2 goals
case false
⊢ Bool
case true
⊢ Bool
-/
```
Then, for the first case that `b` is `false`, `exact true` provides a `Bool` of value `true` so that the derised construction is obtained. Similarly for another case.
```lean
exact true
/-
1 goal
case true
⊢ Bool
-/
exact false
-- No goals
```

Users can decide the order of cases by
```lean
cases construnctor => ...
```

### `match` tatic

`match` keyword is another way to handle different cases of the input. Compare to `cases` that the constructors(cases) are listed by Lean 4, `match` allows users to specify and type the constructors explictly. The syntax:
```lean
def name : expression := by
  intro variables
  match variables with
    | constructor1 => ...
    | constructor2 => ...
    ...
```

We use the example in `cases` to show a comparison:

```lean
def BoolNot : Bool → Bool := by
  intro b
  match b with
    | false => exact true
    | true => exact false 
```

It is like Piecewise Functions.

The above example can be simplifed into:

```lean
def BoolNot3 : Bool → Bool
  | false => true
  | true  => false
```

`match` is useful for defining certain objects.
